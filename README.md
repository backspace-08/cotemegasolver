## О проекте

COTE Megaverse Solver — решатель для арены 3×3 в [COTE Megaverse](https://github.com/backspace-08/cotemegaverse), Telegram-боте сообщества DCOTE. В PvE основной игры ходы бота считает именно он. CFR (counterfactual regret minimization) — алгоритм для игр с неполной информацией.

Арена — пошаговый бой трёх персонажей против трёх. За ход игрок тратит весь пул действий на атаки, щиты, банк (бонус к бюджету следующего хода) или смену активного. Последняя установка щитов и банка соперника видна только суммой, поэтому решение принимается не по точному состоянию, а по распределению вероятностей скрытой раскладки. Правила целиком — в [RULES.md](RULES.md), они совпадают с основной игрой.

В репозитории — исследовательская часть проекта: правила, модель скрытой раскладки, CFR-бот, Rust-ядро и бенчмарки. Это не бот для Telegram целиком: интерфейс, магазин и PvP живут в основной игре.

## Архитектура

Правила собраны в [`src/cote_megaverse/rules.py`](src/cote_megaverse/rules.py) — эталонный симулятор для партий и замеров; Rust-движок повторяет ту же модель. Модель скрытой раскладки живёт в [`infoset.py`](src/cote_megaverse/infoset.py), бот — в [`cfr_bot.py`](src/cote_megaverse/cfr_bot.py): на каждом ходу он собирает подыгру (часть дерева от текущей позиции), передаёт распределение в Rust и играет корневую стратегию.

Тяжёлая часть вынесена в PyO3-расширение `_cote_cfr` ([`cote_cfr/src/lib.rs`](cote_cfr/src/lib.rs)): поиск по коротким деревьям CFR и оценка листьев. 1v1-листья берутся из таблицы, листья 2v2 и 3v3 считает ChainLeaf — оценка через цепочку дуэлей. Серверные скрипты и сборка таблицы — в [`server/`](server); сама таблица лежит в `cote_cfr/`.

## Инженерные решения

### Continual resolving вместо дерева на весь матч

Полное дерево матча 3v3 слишком велико, чтобы строить его заранее. Офлайн строится только таблица 1v1 для эндшпиля (дуэли с седьмого полухода), а на каждом ходу бот заново решает текущую подыгру. Ранние ходы бот решает поиском, который доигрывает до таблицы; в эндшпиле поиск короткий. Цена решения — сборка таблицы: она требует многоядерного сервера, а без неё дуэльные листья слабее. Зато на замерах ход укладывается в 138 мс.

### ChainLeaf: листья для 2v2 и 3v3

Лист — позиция, где поиск останавливается и вызывает оценку. Материальная эвристика без учёта порядка стека ошибается на асимметричных составах, поэтому для листьев 2v2 и 3v3 используется ChainLeaf — цепочка дуэлей с продвижением по стеку и остаточным HP по обмену уроном. На точном 2v2-минимаксе средняя абсолютная ошибка — 0.019 в шкале от −1 (поражение) до +1 (победа). Старый лист пересчитывался на каждой итерации; ChainLeaf портирован в Rust и считается один раз при построении дерева, поэтому ход стал быстрее, хотя оценка сложнее. Экспериментальный ReBeL-пайплайн для value-net листьев остался в [`server/`](server), но финальная конфигурация использует ChainLeaf.

### Модель скрытой раскладки

Скрыта только последняя раскладка соперника: щиты и банк известны суммой `R = budget − attacks − switch`. Бот не читает скрытое состояние, а держит распределение по паре щитов и банка: жёстко отсекает варианты, противоречащие раскрытиям, и мягко запоминает тенденции по прошлым ходам. Память не обнуляет варианты, поэтому не создаёт ложной уверенности.

## Результаты

Замеры — против Planner, эвристического соперника с альфа-бета поиском. Это не игроки. Матчи дублирующие: каждый сид играется дважды, бот на первом и втором месте, поэтому преимущество первого хода сокращается.

| Конфигурация | Винрейт | ΔScore | Средняя задержка |
|---|---|---|---|
| depth-3, без ChainLeaf | ~48% | −0.06 | 831 мс |
| depth-3 + ChainLeaf | **53.8%** | +0.177 | 138 мс |
| depth-4 + ChainLeaf | 50% | +0.20 | 5568 мс |

ΔScore — средний счёт за пару партий с чередованием мест: победа +1, ничья 0, поражение −1. У depth-4 около 10% ничьих, у финальной конфигурации — около 1%, поэтому ΔScore у depth-4 выше, хотя винрейт ниже. Финальная строка — 10 000 матчей, 95% интервал около ±1 п.п. Для верхних строк точное число партий не сохранилось: это ранние ориентиры, а не сравнение с точностью до п.п.

В чистых дуэлях на равных стартах бот выигрывает 64–75% в эндшпиле, но в ранней игре выходит на паритет около 51%. Это [`test_1v1_duel_bot.py`](test_1v1_duel_bot.py): дуэли 1v1 против Planner, профили E/F/G на седьмом полуходе и I на первом, оба места.

Увеличение глубины до 4 не окупилось: 50% при задержке 5.5 с.

Решатель не идеален: лист 2v2/3v3 не моделирует залп соперника из накопленного банка, а в 1v1/2v1-эндшпилях возможны ничьи. Подробный разбор и замеры — в [PROJECT.md](PROJECT.md).

В основной игре PvE-бот на ноябрь 2026 выиграл 174 из 288 матчей против игроков (60%). Это другая выборка и другие соперники, но показывает, что решатель играет вживую.

## Разработка

Нужны Python 3.11+ и Rust stable. На Windows — MSVC toolchain. Расширение собирается с `abi3-py39`, поэтому wheel подходит и для образа основной игры на Python 3.11, и для локального Python 3.14.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install maturin
cd cote_cfr
maturin develop --release
cd ..

pip install -e .
python -m unittest discover -s tests
```

Тесты покрывают правила, модель скрытой раскладки и Rust-движок. Для локальных замеров движок имеет смысл собирать с `RUSTFLAGS="-C target-cpu=native"`; серверный скрипт выставляет этот флаг сам.

### Игра и замеры

[`play.py`](play.py) — headless-партия с ботом. Если таблица ещё не собрана, используйте `--bot planner`.

```bash
python play.py new --seed 1
python play.py view
python play.py move "a1"
python play.py session --games 20

python cfr_vs_planner.py --games 200 --workers 8
python test_1v1_duel_bot.py --profile E --pairs 50
```

`move` принимает атаки, щиты, банк и необязательную смену: `"a2,d1,b1"`, `"2,1,1,2"` или `"a2,sw2"`. Сессии и JSON-логи складываются в `runs/` и не попадают в git.

### Таблица 1v1

Таблица `cote_cfr/1v1_table.csv` не входит в репозиторий: это отдельный артефакт для эндшпиля. Она весит около 5 МБ, а на 64 vCPU (56 воркеров) собирается порядка 45 минут; точное время зависит от CPU. В основной игре файл кладут в `cote_cfr/1v1_table.csv` перед сборкой образа, и Dockerfile копирует его внутрь. В git таблицы нет.

Собрать её можно так:

```bash
bash server/rebuild_1v1_table.sh --all
```

Скрипт [`server/rebuild_1v1_table.sh`](server/rebuild_1v1_table.sh) готовит окружение, собирает движок и таблицу, затем запускает бенчмарк.

## На чём основано

- [DeepStack](https://arxiv.org/abs/1701.01724) — идея continual resolving.
- [ReBeL](https://arxiv.org/abs/2007.13544) — идея value-net листьев; в финальной конфигурации не используется.
- [CFR](https://papers.nips.cc/paper_files/paper/2007/hash/08d98638c6fcd194a4b1e6992063e944-Abstract.html) и [CFR-D](https://aaai.org/papers/8810-solving-imperfect-information-games-using-decomposition/) — базовый алгоритм и декомпозиция.
